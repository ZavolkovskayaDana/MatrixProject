# Matrix Console Animation

Учебный проект по дисциплине **«Программирование»**  
Язык: **C++ / WinAPI**


## Описание проекта

Данный проект представляет собой серию лабораторных работ по дисциплине **«Программирование»**.  
Основная цель проекта — разработка **консольного приложения на языке C++** с использованием  
**объектно-ориентированного подхода**.

В процессе выполнения лабораторных работ поэтапно реализуются и закрепляются:

- принципы объектно-ориентированного программирования;
- работа с консолью Windows через WinAPI;
- динамическое управление объектами;
- обработка пользовательского ввода;
- структурирование кода по классам;
- ведение разработки с использованием Git и системы веток.

Проект реализует консольную анимацию в стиле **«Матрицы»**, которая постепенно усложняется  
от лабораторной работы к лабораторной.


## Стек технологий

- **Язык программирования:** C++ (стандарт **C++17**)
- **Компилятор:** MSVC (Microsoft Visual C++)
- **IDE:** Visual Studio
- **WinAPI:**  
  управление консолью (размеры буфера, курсор, цвета, отрисовка символов)
- **Git / GitHub:**  
  контроль версий, работа с ветками
- **CMake:** не используется (сборка средствами Visual Studio)

## Отличия веток лабораторных работ

### lab-01 — базовая реализация

В первой лабораторной работе реализованы:

- классы:
  - `Line`
  - `Symbol`
  - `SystemUtils`
  - `AppManager`
- движение линий символов по экрану;
- работа с консолью Windows через WinAPI;
- диалоговый режим и режим командной строки;
- проверка корректности пользовательского ввода;
- базовая архитектура проекта.

---

### lab-02 — зигзагообразное движение и управление временем

Во второй лабораторной работе проект был расширен и улучшен:

- добавлено **зигзагообразное движение линий** по вертикали;
- реализованы **безопасные границы** движения по высоте консоли;
- добавлена логика **плавного появления и исчезновения линий**;
- реализована корректная обработка достижения правой границы экрана;
- введён метод `canStep()` — каждая линия движется **независимо от FPS**;
- улучшена логика генерации стартовых позиций линий;
- добавлена настройка **частоты появления линий**.

Архитектура проекта сохранена, логика расширена без переписывания базовых классов.

---

### lab-03 — абстракция фигур и взрывы

Третья лабораторная работа направлена на углубление ООП и полиморфизма:

- введён **абстрактный базовый класс `Figure`**;
- все отображаемые объекты (линии и взрывы) обрабатываются через единый интерфейс;
- реализован класс `Explosion`:
  - анимация расширяющегося кольца;
  - независимая скорость взрыва (не зависит от скорости линий);
  - случайные символы и индивидуальные цвета для каждого элемента взрыва;
- управление созданием и удалением объектов полностью перенесено в `AppManager`;
- реализована корректная работа с **виртуальными деструкторами**;
- добавлена система запросов событий (линия запрашивает взрыв, менеджер создаёт его);
- исключена полная перерисовка линий — обновляются только изменяющиеся элементы.

Проект стал расширяемым и готовым к добавлению новых типов фигур.

---

### lab-04 — собственные контейнеры и обобщённое хранение данных

Четвёртая лабораторная работа посвящена структурам данных и шаблонам:

- создан абстрактный интерфейс контейнера `List<T>`;
- реализован связный список `LinkedList<T>`:
  - `push_back`
  - `insert`
  - `erase`
  - `at`
  - `size`
  - `clear`
- реализован динамический массив `ArrayList<T>`;
- стандартные контейнеры STL (`std::vector`) **заменены на собственные контейнеры**;
- `AppManager` теперь работает с контейнерами через абстракцию `List<T>`;
- один и тот же код может использовать разные контейнеры без изменений логики;
- продемонстрированы:
  - шаблоны (`template`)
  - полиморфизм контейнеров
  - ручное управление памятью
  - сравнение производительности структур данных.

Архитектура проекта стала полностью независимой от STL и ориентированной на расширение.

---

Каждая следующая лабораторная работа **расширяет функциональность предыдущей**,  
сохраняя общую архитектуру и демонстрируя постепенное усложнение проекта.

## Запуск приложения:

Программа может работать в двух режимах:

1. Диалоговый режим
Запуск без аргументов:

Matrix.exe

Пользователь вручную вводит параметры:
скорость;
длину линии;
флаг эпилепсии (Y/N).

2. Режим командной строки
Запуск с аргументами:

Matrix.exe <speed> <length> <Y|N>

Пример:

Matrix.exe 10 15 Y

Где:
speed — целое число 1–30 (чем меньше, тем быстрее анимация),
length — длина линии (1–30),
Y/N — режим эпилепсии, строго один символ.

Дополнительная информация

По команде:

Matrix.exe --help выводится справка по использованию программы.
